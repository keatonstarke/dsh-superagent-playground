## 1. 决策背景：为什么从 Pro 转到 3.8 Flash

前篇的结论是"Pro 级没有 API 免费层，只剩订阅配额/付费 API/号池"。在"调用量很大"的前提下：

- 付费 3.1 Pro 单轮 $0.026，是 3.8 Flash 的 **2.9 倍**；20k 轮/日就是 $15.6k/月 vs $5.4k/月。
- 订阅 Pro $19.99 给的是 Argon，不是 3.1 Pro；Argon 只支持隐式缓存、12 月起涨价，RP 成本反而高于 3.8 Flash。
- 号池/共享池有封号与内容外泄风险（前篇 §4.5）。

所以"用 3.8 Flash"不是妥协，而是在 **RP 这个具体任务**上做了正确的性价比选择。前提是把它的两个短板（thinking 成本、细节保持）用工程手段补上。

### 3.3 中文社区反馈 `[第三方]`

- 正面：中文写作"清晰、看得舒服、回答快"，写小说"比 GPT 系更说人话"。
- 负面：**指令遵循和注意力弱**，复杂设定容易流于字面；"角色全知"、极端情绪、强行冲突；设定与模型世界知识冲突时，开头就写错。
- 结论：**日常/中短篇/快节奏 RP 很合适；重设定、长线、细节控需要账本和检测器兜底。**

## 4. 成本模型

### 4.1 单轮成本（40k 输入 / 900 输出）

| 场景 | 无缓存 | 90% 缓存 |
| --- | --- | --- |
| 3.8 Flash（2026） | $0.0334 | **$0.0091** |
| 3.8 Flash（2027） | $0.0668 | **$0.0182** |
| 3.6 Flash（2026） | $0.0334 | $0.0091 |
| 3.5 Flash-Lite | $0.0143 | $0.0045 |
| 3.1 Pro | $0.0908 | $0.0260 |

> 计算：`4k×$0.75/M + 36k×$0.075/M + 900×$3.75/M = $0.003 + $0.0027 + $0.003375 = $0.009075`。

### 4.2 thinking 是最大的变量 `[官方+第三方]`

- 默认 `medium`；官方说 3.8 Flash "can use more tokens on longer running and complex tasks, by design"。
- 第三方（Artificial Analysis）测得 high 档约 **48k 输出 token/任务**，比 3.7 Flash 多 30%。
- 对 RP 的含义：每多 1k thinking token，单轮多 $0.00375；多 5k 就多 $0.01875（超过正文成本的两倍）。

| thinking | 估计 thinking token/轮 | 单轮成本（90% 缓存） | 相对 low |
| --- | --- | --- | --- |
| low | 0~500 | $0.0091~$0.0110 | 1.0× |
| medium（默认） | 1,000~3,000 | $0.0129~$0.0204 | 1.4~2.2× |
| high | 3,000~8,000 | $0.0204~$0.0391 | 2.2~4.3× |

**动作**：RP 一律 `thinking_level=low`；在网关记录 `thinking_tokens / output_tokens`，超过 0.3 告警。

### 4.3 规模成本（90% 缓存）

| 日轮次 | 月轮次 | 3.8 Flash 2026 | 3.8 Flash 2027 | 3.5 Lite | 3.1 Pro |
| --- | --- | --- | --- | --- | --- |
| 1,000 | 30k | $272 | $545 | $136 | $780 |
| 5,000 | 150k | $1,361 | $2,723 | $679 | $3,900 |
| 20,000 | 600k | $5,445 | $10,890 | $2,718 | $15,600 |
| 50,000 | 1.5M | $13,613 | $27,225 | $6,795 | $39,000 |
| 200,000 | 6M | $54,450 | $108,900 | $27,180 | $156,000 |

> 以上不含重试、thinking 超标、跨 200k 加价；预算乘 1.2~1.4。Batch/Flex 可再打五折，但只适合离线/非实时。

### 4.4 缓存：3.8 Flash 几乎无脑开

```
存储成本 = $0.50 / 1M / 小时
缓存读节省 = ($0.75 − $0.075) / 1M = $0.675 / 1M / 次
平衡点 = 0.50 / 0.675 ≈ 0.74 次/小时
```

同一前缀每小时用 1 次就回本。40k 前缀的存储是 $0.02/小时，一次命中省 $0.027。**只要会话不是几小时才说一句，显式缓存必开。**

注意：显式缓存最小 4,096 token；规则 + 角色卡 + 固定世界观要凑够。前缀必须逐字节一致，别把时间戳、用户名、随机 ID 放进去。

## 5. 质量边界：3.8 Flash 能写到什么程度

### 5.1 能稳定做到的

- 中短篇场景、日常对话、情感铺垫、快节奏冒险。
- 多角色切换（XSCT 中文用例 91 分，但该站缺少同用例跨模型对照，只作参考）`[第三方]`。
- 遵守 6~8 条以内的硬规则；POV/时态在探针里 0% 违规。
- 低拒绝率、高完成率：适合"不想被频繁打断"的 RP。

### 5.2 容易翻车的

| 问题 | 证据 | 工程对策 |
| --- | --- | --- |
| 细节丢失 | detail-loss 2/9 `[第三方]` | 账本记录道具/伤势/时间/位置；每轮注入；关键细节在正文后追加"连续性校对" |
| 便利的世界 | 主要缺陷之一 `[第三方]` | 规则：解决方案必须来自已建立的事实；禁止天降巧合/新角色救场 |
| 把情绪讲出来 | 主要缺陷之一 `[第三方]` | 规则：情绪只通过动作、生理反应、对话潜台词；禁止"他感到……" |
| 复读描写 | 短语重复率 0.041，仍高于 Grok 的 0.015 `[第三方]` | 禁用词表 + 每场景轮换意象 + 4-gram 检测，超阈值重写 |
| 设定冲突/字面理解 | 中文社区反馈 `[第三方]` | 设定写成"事实条目"而非散文；关键设定在 system 和 user 各强调一次；用 judge 检查 |
| 角色全知 | 社区反馈 `[第三方]` | 反全知条款 + 知识边界字段 + "只能基于可观察线索推断，可以推断错" |
| 长上下文注意力弱 | 社区反馈 `[第三方]` | 窗口压到 20k~30k；每 15~20 轮摘要；lore 检索代替全量 |
| 硬边界场景 | 非自愿/破框探针只过一半 `[第三方]` | 明确成年/同意/边界；关键场景换更稳的模型或暗场处理 |
| thinking 吃掉预算 | 官方 + AA 数据 | `thinking_level=low`；`max_output_tokens` 上限；监控 thinking 占比 |

### 5.3 什么时候仍然值得上 3.1 Pro

- 单场景要求高细节一致性（推理、法庭、复杂战斗空间）。
- 用户手动点"高质量"或章节收束。
- 自动检测连续失败（账本矛盾、复读、OOC）时，升级一次 Pro 重写。
- 建议比例：**5%~10% 的轮次**；成本增加约 10%~20%，但能显著降低"关键场景翻车"。

## 6. 工程配置

### 6.1 参数

| 参数 | 建议 | 原因 |
| --- | --- | --- |
| `thinking_level` | `low` | 默认 medium 会多用 token；high 在 RP 上纯浪费 |
| `max_output_tokens` | 1,600~2,000 | 正文 600~1,000 + 余量；防 thinking 挤断 |
| `temperature` / `top_p` / `top_k` | **不要传** | 2026-07-21 起废弃；默认 1.0 |
| prefill | 不要用 | 3.8 Flash 起移除 prefilled model turns |
| `safety_settings` | 默认（Off） | 四类过滤器默认 Off；调严只会增加误杀 |
| 流式 | 必开 | 首 token 体验 + 可中断 |
| 缓存 | 显式缓存 canon | 输入成本降到 1/10 |

### 6.2 Prompt 骨架（3.8 Flash 特化）

```text
<system>
你是互动小说的叙述者，兼任所有 NPC。玩家扮演主角；不替主角做决定、不写主角台词。

[硬规则]（最多 7 条，开头和结尾各重复一次）
1. 角色不是全知的：只能基于对话、动作、表情、环境推断；推断可以错。
2. 情绪只通过动作、生理反应、对话潜台词表达；禁止"他感到/她意识到"。
3. 解决方案必须来自已建立的事实；禁止天降巧合、新角色救场、无铺垫的能力。
4. 外貌/体格是固定数值；禁止升级形容词和无依据的力量展示。
5. 时间/地点/伤势/物品以 LEDGER 为准；冲突时以 LEDGER 为准。
6. 不复述玩家刚说的话，不复述上一段。

[STYLE BIBLE]

- 禁用词/意象：{{BANNED_LIST}}（每章轮换）
- 禁止总结上文、解释主题、替读者下结论。

[CHARACTER CARD]
姓名/年龄/身份：
外貌（固定数值）：
口吻样本（3~5 句原话）：
欲望/恐惧/底线：
知识边界（不知道什么）：
关系状态：

[STATE LEDGER]
{{LEDGER_JSON}}

[CANON]
{{WORLD_LORE_TOP_K}}

[本轮场景]
时间/地点/在场者/环境线索：{{SCENE_BLOCK}}
玩家动作：{{USER_INPUT}}

[再强调]
不替玩家做决定；情绪用动作写；解决方案来自已建立事实；时间/地点/伤势/物品以 LEDGER 为准。

[输出]
600~1,000 字；以 hook 结尾；不要写"未完待续"。
```

### 6.3 上下文预算（3.8 Flash）

| 层 | token | 更新 |
| --- | --- | --- |
| 规则 + 风格 + 角色卡（缓存前缀） | 3,000~5,000 | 固定 |
| 世界观检索 top-k | 1,000~3,000 | 每场景 |
| 账本 | 300~800 | 每轮 |
| 摘要 | 500~1,000 | 每 15~20 轮 |
| 近期原文 | 10,000~20,000 | 每轮 |
| 本轮输入 | 50~300 | 每轮 |
| **合计** | **15k~30k** | 不要超过 40k |

3.8 Flash 虽然支持 1M，但注意力与细节保持会随上下文下降；**主动压到 30k 以内**比"塞满 1M"更稳、更便宜。

### 6.4 每轮流水线

```
用户输入
  → 组装（canon cache + ledger + summary + window + scene）
  → 3.8 Flash（thinking low, max 2000, stream）
  → 后处理：
      · 4-gram 重复检测
      · 禁用词/句式检测
      · 账本一致性（Flash judge）
      · POV 违规（第二人称/代写）
  → 失败：重写一次（同模型，调整提示）→ 再失败升级 3.1 Pro
  → 成功：更新账本（Flash，JSON）→ 每 N 轮摘要
```

## 7. 免费/低价路径的产能上限

| 路径 | 3.8 Flash 可用 | 产能 | 适合 |
| --- | --- | --- | --- |
| AI Studio 网页 | ✅ | 人工，限流 | 调 prompt |
| Gemini API 免费层 | ✅ | RPM/TPM/RPD 限流（AI Studio 查看），数据用于训练 | 开发、评测、灰度 |
| Antigravity 免费层 | ✅ | 周配额，按"工作量"扣 | 个人轻量使用 |
| Gemini App 免费层 | ❌ | 只有 3.6 Flash，32k | 人工玩 |
| 付费 API Tier 1 | ✅ | $10/10min 花费上限（≈$1,440/日） | 小产品 |
| 付费 API Tier 2/3 | ✅ | $200/10min + 更高 TPM | 高调用量 |
| Batch | ✅ | 五折，24h 目标 | 离线批量 |
| Flex | ✅ | 五折，延迟不保证 | 非实时补全 |
| Antigravity 多账号 | ✅ | 周配额 × N，但封号/ToS 风险 | 不建议做主链路 |

**结论**：3.8 Flash 的付费价已经足够低，"大调用量"没必要冒险堆免费号；免费层只用来做开发和回归。

## 8. 高调用量架构（Flash-first）

```
client
  │
  ▼
gateway
  ├─ 3.8 Flash（主力，thinking low，显式缓存）
  ├─ 3.6 Flash（兜底：要 minimal / 更低延迟 / 3.8 故障）
  ├─ 3.1 Pro（升级：关键场景 / 自动检测失败 / 用户手动）
  └─ 3.5 Flash-Lite（工具：摘要、账本、分类、检测）
        │
        ▼
  Redis: 会话/额度/健康分
  Postgres: 正文/账本/摘要
```

**路由规则**：

| 条件 | 路由 |
| --- | --- |
| 默认 | 3.8 Flash，thinking low |
| 首 token P95 > 4s 或 429 | 3.6 Flash，minimal |
| 检测失败 2 次 / 用户点高质量 / 章节收束 | 3.1 Pro，thinking low |
| 摘要/账本/检测 | 3.5 Flash-Lite |
| 离线分支/夜间批跑 | Batch 3.8 Flash（五折） |
| 非实时补全 | Flex 3.8 Flash（五折） |

**容量**：20k 轮/日 ≈ 2.2 并发、27.8M TPM 峰值；200k 轮/日 ≈ 22 并发、278M TPM。并发不是问题，TPM 和花费上限才是。

**观测**：每轮记录 input/cached/output/thinking、首 token、finishReason、后处理失败原因；按模型/场景聚合成本与质量。

## 9. 评测与验收

### 9.1 A/B 设计

- 同一评测集（50 场景 × 20 轮），三组：3.8 Flash low、3.6 Flash minimal、3.1 Pro low。
- 盲评 100 轮，记录：细节保持、复读、指令遵循、OOC、每轮成本。
- 指标：
  - 细节保持：账本矛盾率 < 2/会话
  - 复读：4-gram < 0.08
  - 指令遵循：硬规则违规 < 1/10 轮
  - 每美元质量：人工评分 / 成本
- 验收：3.8 Flash 的综合评分不低于 3.1 Pro 的 90%，成本低于 50% → 通过。

### 9.2 陷阱探针（照 PlotPoints 的思路）

| 探针 | 检查 |
| --- | --- |
| 主体性 | 是否替玩家做决定/写台词 |
| POV/时态 | 是否破坏第三人称限知 |
| 细节 | 道具、伤势、时间、位置是否一致 |
| 矛盾 | 前后事实冲突是否被"圆"过去 |
| 便利 | 是否出现无铺垫的巧合/救援 |
| 情绪 | 是否直接写"他感到" |
| 角色扁平 | 是否只剩一个标签 |
| 类型漂移 | 是否从悬疑写成喜剧 |

### 9.3 上线闸门

- 3.8 Flash 的 P95 首 token < 3s；
- 后处理失败率 < 5%；
- 升级到 Pro 的比例 < 10%；
- 每轮综合成本 < $0.012（含重试/摘要/检测）。

## 10. 推荐方案

| 规模（轮/日） | 配置 | 月成本 `[估算]` | 关键动作 |
| --- | --- | --- | --- |
| < 1,000 | 免费层为主 + 付费 API 兜底 | $0~$270（免费层为主时接近 $0） | 调 prompt、建评测集；thinking low |

| 10,000~100,000 | 3.8 Flash + 3.6 兜底 + 5% Pro | $2.7k~$27k | Tier 2；缓存命中 > 60%；检测器；预算闸门 |
| > 100,000 | Vertex/Enterprise + 预留吞吐 | $27k+ | 多项目/多区域；SLA；专职工信 |

**省钱优先级**：

1. `thinking_level=low`（省 30%~70% 输出）
2. 显式缓存 canon（省 80%~90% 输入）
3. 窗口压到 30k + 每 15 轮摘要
4. Pro 只留 5%~10%
5. Batch/Flex 处理离线/非实时

## 附录 B. 成本脚本

```python
PRICES = {
    "flash-2026": (0.75, 0.075, 3.75),
    "flash-2027": (1.50, 0.15, 7.50),
    "lite":       (0.30, 0.03, 2.50),
    "pro":        (2.00, 0.20, 12.00),
}

def turn(model, inp=40_000, out=900, cache=0.9):
    pi, pc, po = PRICES[model]
    cached = inp * cache
    return (inp - cached) * pi / 1e6 + cached * pc / 1e6 + out * po / 1e6

for m in PRICES:
    one = turn(m)
    print(f"{m:11s} ${one:.4f}/轮  20k/日 ${one*20_000:,.0f}  月 ${one*20_000*30:,.0f}")
```
